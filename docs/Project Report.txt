# ASYNCHRONOUS FIFO — COMPLETE DESIGN & UVM VERIFICATION REPORT

---

# 1. PROJECT OVERVIEW

## 1.1 Objective

The project implements and verifies a **clock domain crossing (CDC) safe asynchronous FIFO**.

The verification environment is built using **UVM (Universal Verification Methodology)** and generated using **Easier UVM Code Generator templates**, then customized.

The goals of the project:

* implement a **correct asynchronous FIFO architecture**
* verify correctness using **UVM transaction-based verification**
* create **self-checking verification infrastructure**
* simulate realistic concurrent read/write scenarios
* validate FIFO ordering behavior under asynchronous clocks

---

# 2. DESIGN FUNCTIONALITY

The FIFO allows **data transfer between two clock domains**.

Two independent clock domains exist:

| Domain       | Clock     |
| ------------ | --------- |
| write domain | write_clk |
| read domain  | read_clk  |

This creates a **clock domain crossing (CDC)** problem.

The FIFO safely transfers data using:

* **Gray-coded pointers**
* **2-flip-flop synchronizers**
* **pointer comparison logic**

---

## Data width

```text

```

## Pointer width

```text
4 bits
```

This supports:

```text
2^4 = 16 address entries
```

FIFO depth:

```text
16 entries
```

Write pointer maintained in **binary and Gray code**.

Binary pointer used for:

```text
memory addressing
```

```text
clock domain crossing
```

Conversion:

```text
binary → gray
```

---

## Read pointer

Similarly implemented.

```text

```

Gray pointer used for CDC.

---

# 6. GRAY CODE USAGE

Gray coding ensures:

```text
only one bit changes per increment
```

This minimizes metastability risk.

Conversion formula:

Binary → Gray:

```
gray = binary ^ (binary >> 1)
```

Gray → Binary uses iterative XOR reconstruction.

---

# 7. POINTER SYNCHRONIZATION

Pointers crossing clock domains must be synchronized.

Two synchronizers exist:

| Synchronizer                     | Direction |
| -------------------------------- | --------- |
| write pointer sync → read domain |           |
| read pointer sync → write domain |           |

Each synchronizer:

```text
2 flip-flops
```

Purpose:

```text
reduce metastability probability
```

---

# 8. FIFO STATUS FLAGS

## FULL detection

FIFO is full when:

```text
write pointer next == read pointer with MSBs inverted
```

This is a standard async FIFO full condition.

---

## EMPTY detection

FIFO empty when:

```text
read pointer == synchronized write pointer
```

Meaning no data available.

---

# 9. WRITE OPERATION

Write occurs when:

```text
wr_en && !full
```

Operation sequence:

1. data written into memory
2. write pointer increments
3. pointer converted to Gray
4. Gray pointer synchronized to read domain

---

# 10. READ OPERATION

Read occurs when:

```text
rd_en && !empty
```

Sequence:

1. read data from memory
2. read pointer increments
3. pointer converted to Gray
4. synchronized to write domain

# 17. DRIVER BEHAVIOR

## Write driver

Operation:

```
data_in <= transaction.data
wr_en = 1 for one cycle
```

Reset procedure included.

Reset sequence:

```
assert rst
wait 5 cycles
deassert rst
```

Reset executed only once using:

```
static bit first
```

---

## Read driver

Read driver continuously checks:

```
if (!empty)
   rd_en = 1
```

Then deasserts after one cycle.

# 19. SCOREBOARD DESIGN

The scoreboard verifies FIFO correctness.

Implementation:

```
bit [7:0] expected_q[$]
```

Dynamic queue used as reference FIFO model.

---

## Write handling

When write transaction received:

```
expected_q.push_back(data)
```

---

## Read handling

When read transaction received:

```
exp = expected_q.pop_front()
compare exp vs actual
```

---
